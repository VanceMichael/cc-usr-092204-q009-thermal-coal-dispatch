# 电煤库存联动调度：需求与不变量

本文把迎峰度夏期间煤矿、铁路、电厂三方的滚动调度要求固化为可核对的规则。实现代码见 `src/dispatch.js` 与 `src/instruction-store.js`，交换结构见 `contracts/`，样例见 `fixtures/rolling-plan.json`。

## 1. 角色与确认边界

- 矿区：确认装车（LOAD）与退运（RETURN）事件。
- 铁路：确认在途（IN_TRANSIT）事件与线路能力、车底周转数据。
- 电厂：确认到厂（ARRIVE）事件与日耗、库存报送。
- 调度中心：编制滚动计划、发起紧急倾斜、执行重大人工改序。
- 审计人员：只读，核对每次优先保障的依据链。

每条物流事件只能由其所属环节的一方确认；确认人角色与事件环节不匹配时，事件不得入账（`assertConfirmer`）。

## 2. 滚动计划

计划以日为粒度滚动编制，汇成以下输入：

- 电厂日耗与当前库存（安全天数的分子分母）；
- 煤矿可装量、线路能力、车底周转（三类能力约束）；
- 高温影响（按温度区间折算的日耗系数）；
- 既有合同（已承诺量，是可行性测算的底线）。

预测修订只能影响尚未执行的区间：计划携带 `frozenThrough`（冻结截止日），任何修订区间与 `[start, frozenThrough]` 相交即拒绝（`revisePlan`）。已执行区间是三方已确认的事实，不允许回溯改写。

## 3. 安全天数与缺口

- 高温折算：日耗 × 温度区间系数（`heatAdjustedBurn`）。
- 库存投影：逐日推演 库存 = 前日库存 − 折算日耗 + 当日已承诺到货（`projectInventory`）。
- 缺口：投影库存 < 安全天数 × 折算日耗 的最早日期及缺口量，供值班员提前数日看到（`firstGap`）。
- 可行替代：区域某日的可再安排量 = min(煤矿可装, 线路能力, 车底能力) − 已承诺量，不为负（`feasibleAlternatives`）。

## 4. 紧急倾斜

触发与记录（`recordPriorityDecision`）：

1. 触发时必须给出量化的缺口证据（触发阈值、当前安全天数、缺口量），缺一拒绝；
2. 必须列出被挤占的既有订单，并把这些订单置为 `preempted`，倾斜订单置为 `prioritized`；
3. 决策编号按 `PD-日期-序号` 生成，连同理由一并落档，审计人员可据此解释每次优先保障为何成立。

## 5. 数量守恒

同一批煤在 装车 → 在途 → 到厂 之间流转，退运从任一环节反向冲减。守恒式（`checkBatchConservation`）：

> 装车量 = 在途量 + 到厂量 + 退运量

装车是批次的起点事件，未装车不得出现在途/到厂；在途量不得超过装车量；到厂量不得超过在途量。任一环节超量即判定不守恒。

## 6. 幂等与迟到数据

- 幂等：同一事件编号重复报送只入账一次（`recordMovement` 对重复 `eventId` 返回 `duplicate: true`）。
- 跨时区晚到：报送携带源时区，业务日期一律按 UTC 换算（`businessDate`）；迟到数据只影响业务日期之后的区间，已执行区间不被改写（`applyLateStockReport` 返回 `adjustsFrom`，调用方据此限定重算范围）。

## 7. 人工改序与指令恢复

- 重大人工改序（`major: true`）必须双人批准且两人不得相同（`assertReSequencingApproval`）。
- 调度指令以追加日志持久化（`src/instruction-store.js`）：每次状态迁移追加一条记录，重启后按日志重放恢复；未完成（非终态）指令可单独列出，继续推进。指令状态机：拟令 → 已下达 → 已确认 → 执行中 → 已完成 / 已取消。

## 8. 两类视图

- 值班员：未来数日的缺口（日期、缺口量）、可行替代（区域、日期、可再安排量）与影响范围（被挤占订单清单）。
- 审计人员：每次优先保障的完整依据链——触发阈值、当时安全天数、缺口量、被挤占订单、理由与决策编号。
